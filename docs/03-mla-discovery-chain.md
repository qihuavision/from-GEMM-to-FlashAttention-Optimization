# MLA 四幕发现链：从 MHA 的病到"存源不存像"

> 按"病 → 论文发现多余的东西 → 操作 → 有无损耗"记架构演进——比背结论好记得多，面试被追问也不怕。

## 第一幕：MHA 的病（2017）

decode 每 token 读 128 头 × 256 维 KV = **3.9MB/token**——瓶颈是读带宽。问题变成：这里面多少是多余的？

## 第二幕：MQA 的发现（Shazeer 2019）——"头间统计重复"

- **发现**：统计上头间 KV 高度相关——多余的是头之间的重复
- **操作**：最狠的删除，128 份全共享成 1 份（单写头）
- **损耗**：有损——一种相似性度量喂所有头，质量明显掉
- 结论：冗余是真的，但没多余到可以全删

## 第三幕：GQA 的发现（Ainslie 2023）——"删过头了"

- **发现**：全共享删过头了
- **操作**：分 g 组共享 + uptraining（组内 K/V 投影均值池化 + ~5% 预训练算力重训）
- **损耗**：半无损（靠重训补偿）——但压缩率仍锁死在"份数"这个离散旋钮上

## 第四幕：MLA 的发现（DeepSeek-V2 2024）——"冗余是结构性的"

回头看 MHA 公式：

```
每个头的 K_h = W_h · h        ← 源是同一个 h！
每个头的 V_h = W_h' · h

128 份 KV 不是 128 个独立信息源——
它们是同一个 h 的 128 张线性投影像。
```

- **操作**：**不存像、存源**——h 经 W_DKV 压到 512 维 latent c 入 cache，用时 W_UK/W_UV 还原各头（投影矩阵是参数，不随 token 增长、不占 cache）
- **"无损"从哪来**：不是复原 MHA 的 K（秩 512 < 16384 数学上不可能），而是**把瓶颈放进训练从头学**——对比 GQA"训完再改造"需要 uptraining 补偿，MLA"生下来就长这样"无需补偿。低秩是换基不是丢信息
- **账**：(512+64)×61 层×2B ≈ **70KB/token**（GQA 244KB 的 28%、MHA 3.9MB 的 1.8%）

### 两个踩坑 = 两个配套发现

1. **RoPE 压不进 c**：旋转 R(pos) 与投影 W 不可交换（R·W ≠ W·R，先转后混 ≠ 先混后转）→ 解耦出 64 维单独存。**位置信息是 KV 里唯一压不掉的部分**——576=512+64 的来历
2. **decode 升维还原贵**：吸收技巧（结合律把 W_UK 挪到 q 侧：q·(W·c)=(q·W)·c）→ **cache 永不解压**，absorbed 形态=576 维 MQA，decode 读带宽差 57×

### 常见误解澄清

- 压缩对象不是"词"而是"token 在该层的 residual stream"——同一个"我"在不同句子里被上下文染色后 h 不同，c 也不同（c 是"词+上下文+层"的指纹）
- MLA 省的是 KV cache（显存/IO），**不省计算**——还原后该算的一样算，投影还多 FLOPs

## 一句话（面试可背）

> "MQA 和 GQA 在讨论'删几份'，MLA 发现 128 份本来就是同一个源投出来的——与其争论删几份，不如直接存源。"
